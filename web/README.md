# web

kc-sim の Web UI。シミュレーションはブラウザ内で動く(sim-core の wasm を Web Worker で実行する)。サーバの
Cloudflare Worker が `dist/` を静的アセットとしてデータ API の隣で配信するので、UI は自分のオリジンの `/api/v1/*` を呼ぶ。
poi プラグイン(`../poi-plugin-sim`)はこのページを iframe に埋め込み、poi の艦隊とマスターデータを
`postMessage` で送り、表示するビューを選ぶ(プロトコル: [`shared/embed/protocol.ts`](../shared/embed/protocol.ts)。プラグインの README に説明がある)。

## ナビゲーション

VS Code 風で、ブラウザとプラグインが 1 つのモデル(`src/app/nav.tsx`)を共有し、1 つのコンポーネント
(`src/ui/AppChrome.tsx`)で描画する。左のアクティビティバー(アイコン + 短い名前、64 px)で機能を切り替え、上の行で
選択中の機能のビューを切り替える(ビューが 1 つの機能は、そこにタイトルを表示する)。右端にバージョンを表示する。

| 機能(バー) | ビュー(上の行) |
|---|---|
| シミュ(シミュレーション) | 出撃(ワークスペース。マップ、艦隊エディタ、結果をページのスクロールなしで 1 画面に置く)、海域(マップとルーティング)、敵艦(敵艦: マスター ID ごとに 1 行、エリート / 旗艦の印、ステータス、装備、サーバの隠しステータスの推定値。`src/app/enemy/`)、計算設定(サーバの推定値を使う、観測を優先する遭遇数)。プラグインでは観測ログと送信設定も |
| 任務 | ビュー 1 つ(前提任務のツリー。下記) |
| 資源 | プラグインのみ: 推移 / 増減 (イベント) / 増減 (日別) |
| 設定(歯車、最下部) | ビュー 1 つ: サンプルデータの切り替え、プリセットの削除、データキャッシュの消去、設定のリセット |

直接開いたときは、このページが持つ機能でバーを描く(観測ログ / 送信設定を除くシミュ、任務、設定)。
プロトコル v3 以降のプラグインの中では、プラグインがバーを描き、表示するビューを送り(`view`)、このページが
自分で移動したとき(海域 →「戦闘シミュ」/「出撃シミュ」、`nav.go({ view: "sortie", … })`)にそれを受け取る。このとき、ページはバーを
描かない。古いプラグイン(v2。自前のヘッダ行が 1 つ)の中では、ページはプラグインのヘッダの下にバーを描く。
現在のビューは `kcsim:view` に保存する(機能を切り替えると、セッション内でその機能の最後のビューに戻る)。
古い `kcsim:tab`(出撃 / 海域 / 敵艦 / 任務 / 設定のバー、`estimate` → `enemy`)は 1 回だけ移行する。2 カラムの
レイアウトは、文書の幅が 928 px(`--breakpoint-lg`)から始まる。プラグインの 1024 px のウィンドウは、iframe に 928 px(1024 − バーの 96 px)を与え、
これは、このページを 1024 px で自前のバーつきで開いたときのコンテンツ幅と同じである。

## コマンド

必要なもの: [bun](https://bun.sh) ≥ 1.3、`wasm32-unknown-unknown` ターゲットを入れた Rust、`wasm-pack`。

```sh
bun install
bun run dev                    # vite on http://localhost:5173, /api → http://127.0.0.1:8787 (KCSIM_API to change)
bun run build                  # wasm-pack (../sim-core) + vite → dist/
SKIP_WASM_BUILD=1 bun run build   # reuse an existing ../sim-core/pkg (also for dev)
bun test
bun run typecheck
```

`bun run dev` は、待ち受けを始める前に `../sim-core/pkg` をビルドし、`../sim-core/src`、`Cargo.toml`、
`Cargo.lock`、`sim_core_types.d.ts` が変わるたび(編集、`git merge` / `pull`)に再ビルドする。新しい pkg でページは再読み込みされ、
ビルドに失敗するとエラーのオーバーレイに表示される。HMR は TypeScript をすぐに更新するので、再ビルドしないと、新しいランナーが
古い wasm の出さないサマリのフィールドを読んでしまう。`SKIP_WASM_BUILD=1` は既存の pkg を配信し、監視しない。

`dist/`: `index.html`、`assets/`(ハッシュ付きの JS、CSS、`sim.worker-*.js`、`sim_core_bg-*.wasm`)、そして
`../server/dist/maps` があれば(`cd ../server && bun run export:bundle`)`maps/`(`/api` が失敗したときに UI が読む静的なマップのバンドル)。

スクリプト: `bun run sample`(`@kancolle/data` から `src/sampleState.json` を再生成する)、`bun run screenshots`
(`docs/screenshots/` または `SHOTS_DIR`、ファイル名の接頭辞は `SHOTS_PREFIX`。撮った画像のうち README が使うものだけをリポジトリに入れる。API が落ちているとき、たとえば
`KCSIM_API=http://127.0.0.1:9` では静的バンドルを使い、その撮影対象のマップについて API に敵編成がないとき(KCNav の取り込みをしていないローカル D1)は、マップのデータをバンドルから取る。次の場合は失敗する: バーが シミュ / 任務 / 設定 で、ビューが
出撃 / 海域 / 敵艦 / 計算設定 でない、サンプルの艦隊が一度もボスに到達しない、または 1280×800、1200×710、1024×600 で 出撃タブのページまたはタブの内容がスクロールする)、`bun run audit [--offline]`。

## 出撃ワークスペース

レイアウト: 左の列は
編成(プリセットの選択 + ⋯: 名前、司令部レベル、fleet 1〜4 または 連合 = fleet 1 + 2 の poi からの取り込み、新規 / 複製 / 入出力 / 削除)、
艦隊(通常艦隊 / 機動部隊 / 水上部隊 / 輸送護衛部隊 / 遊撃部隊)、艦隊の上の 主力 / 随伴 / 支援 / 友軍 / 基地 のタブ。右の列は、
シミュレーターのツールバーで、使う順に左から、海域(+ イベント海域の難易度)、出撃 / 単一戦闘(ノードと敵
編成つき)、条件(スライダーのアイコン)、そして 自動(チェックボックス)と 実行(再生アイコン + 回数。進捗で塗りつぶされる)が並び、その上に結果がある。
出撃モードには、マップの隣に 目標マス もある(既定はボス。マップごとに `kcsim:workspace` に保存する)。出撃はそのノードで終わり、
主要な率(到達 / 突破 / S勝利 / 旗艦撃沈、ゲージ)はボスの代わりにそれを数える(sim-core の `config.target`)。
条件には、マップの規則の `select` ノードごとに 能動分岐 の選択が 1 つある(選択肢は行き先で表示する)。これもマップごとに保存する。
保存された選択のないノードは `defaults.select`(なければ最初の選択肢)を使う。目標マス が設定されていて、その選択肢が
そこへ到達できないときは、到達できる最初の選択肢を使う(`resolveSelects`)。
敵連合艦隊(たとえば 6-5 M)は随伴艦隊つきで送られ、6 対 12 / 12 対 12 で戦う(陣形 11〜14 →
第一〜第四警戒航行序列)。結果には敵の主力艦隊が先に、そのあと随伴艦隊が並ぶ。左: 1 行の艦隊
サマリ(アイコン: 制空、速力、索敵 Cn1〜4、ドラム缶、電探)と、ゲームと同じ 2 × 3 のグリッドに並ぶ 6 隻
(パネルの幅が 36rem 未満のとき、たとえば 1024 / 1200 px では 1 列でパネル内でスクロールし、名前を読める幅を保つ)。各艦は、
ヘッダ(番号、艦種、名前、Lv)の下に、スロットの列(装備アイコン、名前、★、熟練、搭載)が 1 つ並ぶ。改修、士気、
ステータスは ⋯ の奥にある。右: 主要な率を 0〜100 % の 1 つの目盛りのバーで示し(ボス到達はボスのランクで色分け、突破 = 出撃あたりのボス A 以上、
S勝利 = 出撃あたりのボス S 以上、大破撤退)、補助的な数値(周回、旗艦撃沈、資源/出撃、入渠、護衛退避、出撃間の待ち)と、
詳細のタブ(マス: ランクで色分けした到達のバー、ノードごとの 退避 と 大破撤退。経路: 辺の太さ = 通過
率の経路図。損耗: 艦ごとの損傷、入渠時間、ボーキ、ダメージコントロール、退避。資源。ゲージ(ゲージを設定したとき)。前提)が並ぶ。

出撃 条件 には 5 つのタブがある(`src/app/sim/conditions/`。撤退・消費・ゲージ・マス・資源・艦隊 は `kcsim:workspace` に保存し、ゲージ /
マス と 基地空襲 / 友軍 のノードはマップごとに `sortieMaps` に保存する。開始、フラグ、陣形は保存しない):
- 基本: 夜戦の方針、撤退(大破撤退 `onHeavy`、ダメコン所持艦は進撃 `allowDamecon`、中破撤退 `onModerate`、護衛退避
  `useFcf`。旗艦の指揮施設 107 / 272 / 413 を表示する)、ボス前の消費(洋上補給 `policy.underway`、
  戦闘糧食 `policy.rations`)、開始、能動分岐、フラグ、ノードごとの陣形、フェーズ / ゲージ番号、回数とシード。
- 艦隊(`conditions/ExtraFleets.tsx`。単一戦闘の 条件 にもある): 道中支援 / 決戦支援のオン/オフと種別(編成から / 航空 /
  砲撃 / 長距離雷撃 / 対潜)→ `SortieInput.support {node, boss}`(単一戦闘: `BattleInput.support`。決戦はボスで); 友軍艦隊の
  オン/オフ、到着率 % とノード(既定は 目標マス)→ `friendFleet`; 基地空襲: 到着時に空襲を受けるノード、確率、空襲する
  敵編成のノード → `baseRaids`(単一戦闘: 選んだ編成が、飛行隊を持つすべての基地を空襲する。`baseRaid`)。
- マス: 各ノードのあとの 進撃 / 撤退 / 強行(`policy.advance`: retreat / push)、戦闘ノードごとの 煙幕(`policy.smoke`。
  `shared/sim/nodeEffects.ts` の阻塞気球のノードは 気球 と印を付け、`SortieNode.balloons` として送る)、資源マスと
  揚陸マスの獲得(`SortieNode.resource`)、渦潮の損失(`SortieNode.maelstrom`)。
- ゲージ: 種別 撃破(ボス旗艦撃沈)/ HP / 輸送(TP)と残り(`gauge`)、HP の最終閾値と最終編成、TP の輸送ドラム缶の
  強制と S勝利あたりの TP、追加ゲージ(`gauge.phases`: 種別、残り、フェーズ)、ゲージが破れるまで持ち越す士気
  (`gauge.morale`)、連続出撃(`consecutive`)。
- 資源: 入渠時間(`repair.bucketAboveSec`)を超えたときの 高速修復材 と、エンジンがモデル化していない出撃あたりの費用
  (`extraPerSortie`。支援遠征の費用はエンジンが数える。`supportCostMean`)。

資源 タブは、出撃あたりと、ゲージクリアあたりの、燃料 / 弾薬 / 鋼材 / ボーキ / バケツ / 入渠時間の純増減(平均、中央値、90%)、入渠の費用、基地の費用、使用した洋上補給 / 糧食、ノード効果を示す。ゲージ は、クリアまでの出撃(平均、中央値、90%)、
上限に達した実行、士気の待ち、ゲージあたりの出撃、クリアあたりの資源を示す。
遊撃部隊 は最大 7 隻の単一艦隊で(`striking: true` として送る)、保存された 7 隻の 通常艦隊 は、これとして読み込まれる。

連合艦隊: 主力 と 随伴 は同じパネルで編集する。陣形のリストは 第一〜第四警戒航行序列 に切り替わる
(もう一方の種類の陣形は 単縦陣 / 第四警戒 にフォールバックする)。結果には主力艦隊が先に、そのあと随伴(「随伴 …」)が並ぶ。
支援: 道中支援 / 決戦支援の艦隊(各 6 隻)と 友軍: 友軍艦隊(7 隻、「全艦から選ぶ」で任意のマスター艦)は、
同じパネルで編集し、プリセットに保存する(`supportNode` / `supportBoss` / `friendFleet`)。結果は、ノードごと(マス)に 支援 / 友軍、基地空襲(率。防空の制空状態と失った基地の HP はツールチップ)、支援の費用(資源)を示す。単一戦闘は
支援到達 / 友軍来援 / 防空の制空 を示す。
基地: 最大 3 つの基地航空隊 × 4 飛行隊(航空機のみ。艦の装備と同じように選ぶ。偵察機は 4 機、それ以外は 18 機)で、
それぞれ 出撃 / 防空 / 待機 にできる。出撃 の基地は、現在のマップの選んだノードに 2 波を送り(同じノードを 2 回選ぶと、そこへの 2 波)、
艦隊の戦闘の前に、出撃でも 単一戦闘 でも行う(単一戦闘では、標的がその戦闘のノードである波)。防空 の基地は
基地空襲 を防ぐ(`LandBase.defense`)。待機 の基地は何もしない。空襲を設定すると、飛行隊を持つすべての基地が
被害を受けうる。飛行隊の半径(`api_distance`)とノードの `lbasDistance` で、届かない波は落とされる(sim-core の警告)。
「poi から取り込み」 は、マップの海域の poi の基地を読み込む(なければ最新の海域)。標的は選んだままにする。
艦隊の種類、随伴、支援 / 友軍艦隊、基地航空隊とその標的は、プリセットに保存する。

自動実行(`src/app/sim/useSimRun.ts`): 自動 がオンの間、シミュレーションの入力(艦、装備、
マップ、難易度、モード、条件、推定値の設定。プリセットの名前とメモは含まない)が変わるたび、最後の変更の 300 ms 後に
10,000 回の出撃/戦闘を再実行し、実行中のものはキャンセルする。実行 は、条件で選んだ回数(既定は 100,000)を実行する。
古い結果は薄く表示され、実行 ボタンは進捗で塗りつぶされる。シードは固定なので、艦隊の変種は同じ
乱数列で比較される。マップ、モード、条件、自動 は `kcsim:workspace` に、プリセットは `kcsim:selectedPreset` に保存する。

## 任務タブ

`src/app/quests/QuestTab.tsx`。`GET /api/v1/quests`(データのバージョンごとにキャッシュ: boot ビューの
`dataVersion` が応答の ETag のバージョンと等しい間は保持し、boot が失敗したときは 24 時間)と `shared/quest/tree.ts` を土台に作る。
中でスクロールする、全高の 3 枚のカード(1280×800 / 1200×710 / 1024×600 でページがスクロールしない。
`bun scripts/screenshot-quests.ts` が確認する。このスクリプトは `docs/screenshots/17-quests.png`、`18-quest-progress.png`(
プラグインのカウントつきの一回限りの任務)、`19-quest-filters.png`(絞り込んだ一覧と 選択報酬 つきの任務)、
`24-quest-doable.png`(実施可能 をオンにし、poi の状態を注入したもの)、`25-quest-tree.png`(「すべて開く」のあとの A88 のツリー)も書き出す。すべて
1024×600。完全に展開した A88 または B117 のツリーで、タイトルの幅が約 8 文字より狭いものがあると、これも失敗する)。タブは、
UI 自体から推測できないものだけを表示する。枠付きの状態バッジ、見えているものを言い直すキャプション、出所についての
注釈は置かない。

- **一覧:** コード / 名前 / ID で検索し、3 つのドロップダウンの絞り込み(`QuestFilters.tsx`。`shared/quest/filter.ts` を土台に作る)と組み合わせる。種別(単発 / デイリー / ウィークリー / マンスリー / クォータリー / イヤリー / 期間限定。キーは
  `freq`)と 分類(A 編成 … G 改装、その他。キーは `cat`)は、どちらも wiki のコード(`Bq3`、`2610B3`、`L2610F2`、`Cs8` 季節限定
  → 期間限定)に由来し、状況(未開放 = まだ解放されていない、未達成 = 受注可、遂行中 = 遂行中・達成、達成済、不明。
  poi の任務の状態があるときだけ表示する)もある。各選択肢は、ほかの絞り込みと検索を前提に、何件が残るかを表示する。その下に
  「実施可能」のトグル(下記)があり、ほかの絞り込みを前提に何件が残るかを表示する。オンのときは、除外した 不明 の任務の数を
  注記する。poi の任務の状態と所持リストがないと無効になる(「poi 接続時のみ」)。
  絞り込みは `kcsim:questFilter` に保存する(保存された `open`、つまり以前の 未達成 = 受注可・未開放、は 未開放 + 未達成 として読み込む。
  `doable` のない保存済みの絞り込みは、トグルをオフにして読み込む)。選択は `kcsim:quest` に保存する。任務ごとに状態のドット、
  実施可能 な任務にチェックマーク(条件の一部が確認できなかったときは代わりに「条件未確認」)を表示する。行のツールチップに
  説明、条件、報酬の要約がある。
- **任務:** ヘッダに 種別 と状態(ドット + テキスト)。説明、構造化したクリア条件(オーバーライド、なければ kcwiki-quest-data)、オーバーライドの `note`。poi のデータがあるときは、
  実施可能 でない任務の不足(「不足: 潜水空母/潜水艦 0/2」)と、確認できなかった条件をプレーンテキストで表示する。報酬
  (`QuestRewards.tsx`。プレーンテキスト: 資源は色付きのドットと通常の色の数値、固定のアイテムは「、」でつなぐ、
  選択報酬 のグループごとに「選択1: A / B / C」の行を 1 つ。このとき KC3 のメモの `[獲]` の部分は隠す)。進捗。
  前提任務のツリー(下記)。最下部に、この任務のデータの出所(オーバーライドの参照ページ、kcwiki-quest-data、KC3Kai、kcanotify)へリンクする
  「出典:」の行が 1 つ。
- **前提任務のツリー**(`PrerequisiteTree.tsx`。`shared/quest/tree.ts` の `prerequisiteOutline` を土台に作る)。リンクは 2 種類あり、
  描き分ける。
  - **連鎖:** 前提がちょうど 1 つの任務は、その前提を*同じ*インデントの次の行に置き、縦線が 2 つの状態のドットを
    結ぶ。「下のものを必要とする」という意味である。直線的な連なり(B74 → A71 → B72)は 1 本の列として読める。
  - **分岐:** 前提が 2 つ以上の任務は、それぞれの前提を 1 段(10 px)深くインデントし、▸ のトグルの下の
    肘つきのガイド線でつなぐ。分岐は ID 順に並べる。

  したがってインデントが増えるのはグラフが分かれる箇所だけで、A88 / B117 の 40 件以上のツリーも 5 段以内に収まり、
  すべてのタイトルが 1024×600 で少なくとも約 8 文字の幅を保つ(A88 は、普通のツリーだと 16 段だった)。対象自身の
  前提が最上位になる(1 つだけでも)。グラフは DAG なので、2 回目に到達する任務(共有された
  祖先)は、部分木を繰り返さず、1 行の薄い参照(↰)になる。クリックすると、完全な行まで開き、そこへスクロールして
  強調する。▸ のトグルは、連鎖の先頭と、分岐のあるすべての任務にある
  (連鎖の中の行にはない。連鎖は先頭で畳む)。閉じた行は、隠している任務の数を表示する(「+12」)。
  最初に開くのは、2 番目のインデントの段までと、受注可 / 遂行中 の任務に至るすべての分岐(プレイヤーの
  最前線)で、閉じるのは、前提がすべて 達成済 / 達成 の行と、それより深いものである。「すべて開く」 / 「畳む」で、
  すべて開く状態と、その既定の状態を切り替える。循環は、閉じる辺で切り、未知の ID はそのまま表示する(どちらもツリーの
  下に注記する)。行をクリックすると、その任務を選択する。
- **必要なもの:** 「未達成の前提任務を含む」: ツリーの任務のうち、まだクリアしていないものの条件が挙げる艦と装備を、条件ごとに 1 行にまとめる。同じマスター艦に解決される艦の行は 1 行にする
  (同じ艦を指す、オーバーライドのマスター ID と上流の名前、駆逐 / 駆逐艦)。そうでなければ名前が同じ行を 1 行にする。
  艦の行は、任意の任務が求める最大の数を保つ。各任務はそれぞれの時点で艦を必要とし、艦は
  残るからである(近代化改修の素材と 改修素材 は使い切るので、合計する)。装備は、交換、変換、
  廃棄で使い切るので、合計する。数はプレーンテキストで、不足だけが目立つ: 「0/2」(所持/必要)は赤、それ以外は
  必要な数を薄く表示する(「×4」。poi のデータがなくても)。名前が解決できないときは「?/2」。所持は
  poi の艦と装備から判定する(名前で指定した艦は、その後の改装とも一致する。艦種の語と艦級はマスターデータで解決する。
  オーバーライドはマスター ID、艦種、艦級、装備カテゴリを指定し、これらは厳密に一致する)。空の
  艦娘 または 装備 のセクションは出さない。その下に 後続任務(この任務が解放する任務)が並ぶ。

状態(poi の状態 `quests`、protocol.ts の `PoiQuests`): 達成 / 遂行中 / 受注可 はゲームの一覧をそのまま使う。達成済(推定: 一覧にある
任務の祖先)と 未開放(推定: 一覧にある一回限りの任務のあと)もある。全て の一覧がないとき(poi を再起動して以降、
任務画面を開いていない)は、poi の受注中の任務だけを推定に使う。poi がなければ、すべてが 不明 になり、所持艦との照合も
行わない。

実施可能(`shared/quest/doable.ts` の `questDoability`)は、poi の任務の状態と所持リストがあるときだけ使える。

1. **解放済み:** 状態が 受注可、遂行中、または 達成(未達成 と 遂行中 のグループ)。不明 を解放済みとして数えるのは、poi が
   全て の一覧を見ておらず、かつ前提がすべて 達成済 と推定された任務だけである。
   全て の一覧があるときは、そこにない任務は受注できない(以前にクリア済みか、提示されていない)。前提のない任務からは、
   推定の材料が得られない。そのほかの 不明 の任務は除外して数える(「不明 N 件は除外」)。推定された任務は、
   すでにクリア済み(一回限り)か、時期外(期間限定)の可能性がある。全て の一覧を開くと確定する。
2. **所持:** 任務自身の条件(オーバーライド、なければ kcwiki-quest-data)が挙げるすべての艦、艦種 / 艦級の数、装備が、
   必要な数だけ所持されている。判定と数え方は 必要なもの と同じ(`aggregateRequirements`)。前提任務の経路の必要分は
   数えない。`or` のリストは 1 つの選択肢があればよい(`and` / `then` のリストの `or`: 1 つの組み合わせ)。満たさない任務は、
   最も近い選択肢の不足を表示する。レベル、★、熟練、艦隊の位置は確認しない。
3. **条件未確認:** 構造化した条件がない任務、自由記述の `other` の条件がある任務、マスターデータにない名前がある任務は
   確認できない。そのような任務も 実施可能 として数え、「条件未確認」と印を付ける(詳細にその条件を列挙する)。

進捗のカウント: poi は、`assets/data/quest_goal.cson` にある任務(130 件。実質的にデイリー / ウィークリー / マンスリー / クォータリー / イヤリー)について、関係するすべてのイベントをすでに数えていて、`info.quests.records` に保持している。タブは、
再び数えずに、そのカウント(たとえば `2/5`。サブゴールごとに 1 つ)を表示する。poi が追跡しない受注中の任務については、
プラグインが手書きのオーバーライドの機械的な条件を自分で数え(`shared/quest/overrides.json`。マップごとのボス /
ノードのランクと艦隊の確認、演習、遠征、廃棄、...)、`source: "kcsim"` の `records` のゴールとして送る。タブはそれらに「進捗 (kc-sim)」とラベルを付け、サブゴールごとに 1 行を並べる。そのほかの任務は、ゲーム自身の
`api_progress_flag`(50% / 80%)または 達成 を表示する。

## デザインシステム

トークンは `src/styles.css`(`@theme`)にあり、プリミティブは `src/ui` にある。アイコン: `lucide-react`(インライン SVG、`currentColor`。プラグインの CSS のスコープ下でも動く)と `ui/EquipIcon`(`api_type[3]` による、自前で描いた装備カテゴリのグリフ)。

- 間隔は 4 / 8 / 12 / 16 / 24 px(`1 2 3 4 6`)。角丸は `rounded-md` の 1 種類で、`rounded-full` はメーターとドットだけに使う。
- 面: ページ `ink-950` → パネル `ink-900`(`Card`、枠は全周のヘアライン `ink-800`)→ 浮き上がり/コントロール `ink-800`。ボックスに、片側だけの枠線、
  内側の影の縞、角の装飾を付けない。リストの項目は、間隔か全幅のヘアラインで区切る。
- テキスト: `xs` 11px(キャプション、列の見出し)、`sm` 13px(本文)、`base` 14px(タイトル)、`lg` 20px(主要な数値)。数値は等幅で
  1 列に右揃えにし、単位はインラインに置く。
- 色は意味を表すためだけに使う: `accent` = 操作可能/選択中、`rank-*` = 戦闘ランク、`hp-*` = 損傷状態、ノードの色 =
  ノードの種類、`danger` = 失敗。グラデーション、グロー、OK/NG の色付きの枠、装飾的なバッジ、絵文字は使わない。
- 状態は、色付きの枠ではなく、アイコンの形 + 色またはデータのバーで示す。

## poi のデータ

| ページが動く場所 | poi の状態 |
|---|---|
| プラグインの iframe 内 | プラグインから(`src/poiBridge.ts`) |
| 通常のブラウザ | なし: プリセットは JSON で取り込める。出撃タブは「内蔵サンプルデータを使う」を提供する(同梱のサンプルの艦と装備。オンの間は 設定 の歯車にスイッチを表示する) |
| 親のない `bun run dev` | `myState.json`(ダンプした poi の状態。gitignore 済み)または `src/sampleState.json`。`/__dev/state.json` で配信する |

プリセットと設定は、このオリジンの localStorage(`kcsim:*`)にある。
